# 北邮课程表 · bupt_schedule

一个跑在 OPPO / ColorOS 手机上的**零构建 PWA 课程表**：纯 HTML + CSS + 原生 ES Module，**无 npm 运行时依赖、无 CDN 资源依赖**，课表默认只存在本机 `localStorage`。

覆盖五件事：**教务系统导入**· **课表展示**（时间/课程/地点/教师）· **上课提醒**（原生系统闹钟通知）· **调课更新**（停课/改时间/改教室/补课）· **节假日自动静默**。

> **没有账号、没有服务器**：课表只存这台设备的 `localStorage`，App 不发任何统计/推荐请求。
> 换手机或清缓存请用「设置 → 导出备份（JSON）」搬家。详见 [§8 数据只在本机](#8-数据只在本机没有账号没有服务器)。


---

## 1. 怎么运行（必须有静态服务，不能双击 file://）

`<script type="module">` 与 `navigator.serviceWorker` 都被 `file://` 协议拦截，双击 `index.html` 时页面只会显示一条提示条（不会白屏，但通知、离线、添加到主屏幕全部不可用）。请用任意静态服务器：

```bash
# 方式 A：Python（Windows/macOS/Linux 自带）
cd bupt-schedule
python -m http.server 8080
# 打开 http://localhost:8080

# 方式 B：Node
npx serve . -l 8080
```

> 若宿主环境不方便起服务，也可以用 GitHub Pages / 任意静态托管（把整个目录上传即可，无需构建）。

**演示用快捷入口**：本机没有数据时，打开 `http://localhost:8080/?demo=1` 会自动载入 8 门示例课（含停课/换教室/补课各一条），用于快速评审；正式使用请走「导入」Tab 或首页的「先看示例课表」。

## 2. 安装到 OPPO 手机（ColorOS）

1. 手机上用 **Chrome** 打开上面的地址（同一 Wi-Fi 下可用电脑的内网 IP，如 `http://192.168.1.10:8080`）。
2. Chrome 右上角 **⋮ 菜单 → 添加到主屏幕 → 添加**。
3. 从桌面图标启动（`display: standalone`，无地址栏）。
4. 首次进「提醒」Tab 点 **申请通知权限 → 允许**。
5. 避免后台被清理：**设置 → 电池 → 应用耗电管理 → Chrome → 允许后台活动**（可选，但强烈建议）。
6. 若系统提示「不允许通知」，去 **设置 → 应用管理 → Chrome → 通知 → 允许**。

### 2.1 安卓 App 安装包（推荐，ColorOS 上体验更好）

`android/` 是一个极小的原生壳：一个 WebView 承载整个应用，**所有网页资源打进 APK**，
所以不用起静态服务器、完全离线可用；还多了一条浏览器做不到的通道——**在 App 内直接抓教务系统课表**。

```bash
node scripts/build-android.mjs
# 产物：android/dist/bupt-schedule-1.2.2.apk（已签名，0.2 MB）
```

构建只用命令行工具（aapt / javac / d8 / apksigner），**不需要 Gradle**。路径可用环境变量覆盖：
`ANDROID_SDK_ROOT`（默认 `D:\Android SDK`）、`JAVA_HOME`（默认 `D:\JDK`，JDK 17+ 均可）。

安装（OPPO / ColorOS）：把 APK 传到手机 → 文件管理里点开 → 允许「安装未知应用」→ 安装 → 桌面出现「北邮课程表」。

导入课表：**导入 → 跳转登录 → 「打开教务系统并抓取」→ 用学号密码登录 → App 自动跳到课表页 → 右上角「抓取课表」→ 核对预览 → 确认导入**。

**学期起始周自动识别**：抓取时会一并读课表表头的日期（`周一 08-31 … 周日 09-06`）和右上角的周次（`第1周`），
反推「第 1 周周一」并直接写入学期设置——不用再自己翻校历。优先级：
表头日期（最硬）> 页面写的「当前第 N 周」> 周次下拉选中项（只预选，需你点一下）。
都没读到（比如页面停在「全部」周次）时，预览页会出现「今天是第几周？」下拉，选一次即可。
登录发生在学校自己的页面里，**App 没有任何账号密码输入框**，密码只提交给 `jwgl.bupt.edu.cn`；
抓取时只读课表 DOM，不读表单、不落盘任何凭据（只落盘课表 HTML 到应用缓存）。

技术要点（也是坑）：

| 事项 | 做法与原因 |
|---|---|
| 页面来源 | `https://appassets.androidplatform.net/` + `shouldInterceptRequest` 映射到 `assets/www/`。**不能用 `file://`**：那里 localStorage 是不透明源、ES Module 与 SW 都被拦，课表存不住 |
| 打包工具 | 用 **aapt v1**，不能用 aapt2。Windows 版 aapt2 的 `-A assets` 会把子目录写成反斜杠（`assets/www\src\main.js`），AssetManager 找不到 → 白屏。构建脚本会自检条目名与 `resources.arsc` 是否 STORE |
| Service Worker | App 里**不注册**（资源本来就在本地，SW 只会多一层） |
| targetSdk | 33。不触发 Android 15 强制 edge-to-edge，刘海 / 手势条由系统让位，网页不需要补安全区 |
| 课表地址 | 强智模板各年不同，按 `kbcx/kbxx_xskb` → `xskb/xskb_list.do` → 主页顺序试；都失败就用左侧菜单手动进入「课表查询」再点抓取 |
| 网络 | 需要校园网或学校 VPN（`jwgl.bupt.edu.cn` 只在内网 DNS 解析） |
| 通知 | **原生系统通知**（1.5.0+）：网页算好未来 7 天的提醒点 → 交给 `AlarmManager` 精确闹钟 → 到点由系统发通知，**锁屏 / 清理后台也能响**。需要授予通知权限（13+ 弹窗；ColorOS 再允许「自启动 / 后台活动」） |

**学期（第 1 周周一）也是自动的**：抓取时从页面认出学期代码（`2026-2027-1`）→ 查 `src/semesters.js` 里的内置校历 → 导入时自动写入设置，于是"本周是第几周"立刻是对的。内置校历没有的学期，会退一步用页面上的「当前第 N 周」反推（标注"推定"）；两条都不成立就明确提示去手填，**绝不按"大概九月初"猜**。你自己填过的学期起始日不会被覆盖。

## 3. 导入与更新

### 3.0 更新课表（自动，需先保存一次账号）

「导入」页的**更新课表**卡：保存学号密码 → 点「更新课程表」→ 自动登录抓取 → **只列变化的课程** → 你确认后写入。

变更按课程名比对（教务每次抓取内部 id 都会变，不能用作 key），逐项看 4 件事：

| 类型 | 展示 |
|---|---|
| 新增 | 新课表有、本地没有 → 列出课程与该课时间/地点/周次 |
| 删除 | 本地有、新课表没有 |
| 变更 | 同名课程比较**时间**（星期+节次）、**地点**、**周次**，标出哪几项变了，并给出「原 → 新」 |

边界行为（都有探针钉住）：

- **没有变化** → 页面直接写「课表没有变化，已是最新」，不出现「应用变更」按钮。
- **对比失败**（抓取超时 / 未登录 / 登录页改版 / 解析不出课表）→ 明确显示原因，并注明**本地课表没有被改动**。
- **未确认一定不改**：变更页只是预览，点「保持不变」就原路返回；点「应用变更」才整份写入，同时在「导入历史」留一个可回滚快照。

#### 凭证怎么存（重要）

- 密码用 **Android Keystore**（AES-256/GCM，密钥不可导出，随应用卸载失效）加密后，密文与 IV 存进 **SharedPreferences（MODE_PRIVATE）**。
- **不写 localStorage、不写纯文本文件、不上传**：网页层只能调「保存 / 清除」，**读不回密码**；只有自动登录那一刻由原生解密后填进学校自己的登录页。
- 学号以明文保存（仅用于界面回显「已保存 2021xxxx」），密码永远不回显。
- 自动登录**只在 App 内 WebView 里**进行；失败会明确报「账号或密码可能已变更」，不会重试刷屏。
- 已知边界：root 设备、或系统备份带走了密文并配合同一台机器的 Keystore，理论上仍可解密；**随时可在卡片里「清除已保存的账号」**，清除后立即失效。
- 学校若加了验证码 / 二次验证，自动登录会失败（走 `no_form` 或 `bad_credentials`），此时请手动抓取一次——功能不受影响。

## 3.1 导入流程（一个入口，抓完先核对）

导入页只有一个入口：**登录教务系统并抓取**。抓完不是直接写库，而是先给你一份**课程列表**核对。

### 3.1 App 内（推荐）

1. 「导入 → 登录教务系统并抓取」→ App 内打开教务系统，用学号密码自己登录（密码只提交给学校页面）。
2. 进到课表页后按抓取，回到 App。
3. 页面按**课程**列出结果：每门课的**上课时间**（周几 第几节 · 地点）与**周次**（`4-19(周)` 这类原样保留）。
4. 核对无误 → **确认导入**；想逐格改 → 「逐条核对」二级页（课程名/星期/起止节次/地点/周次都能改）。
5. 解析失败的行不会静默丢弃，会列在「需要留意」里，可补录或忽略。

### 3.2 浏览器 / 网页版（没有内置 WebView 时）

1. 「打开教务系统登录页」→ 登录 → 课表页 **另存为 HTML**（`Ctrl+S`）或复制文字。
2. 回到导入页 → 底部「粘贴文本 / HTML / JSON」→ 选择文件或粘贴 → **解析**。

### 3.3 备用导入的三种格式

| 通道 | 适用 | 说明 |
|---|---|---|
| 粘贴文本 | 复制的文字、OCR 结果 | 支持 3 种写法（见右上角 i 说明） |
| HTML 源码 | 教务系统课表页另存 | 自动判别来源 |
| JSON | 本 App 备份、抓包数据 | 含 `schemaVersion` 校验，高版本明确拒绝 |

## 4. 提醒可靠性说明（请务必读）

提醒有三条腿，**安卓 App 里主通道是原生系统通知**（1.5.0 起）：

| 通道 | 可靠性 | 说明 |
|---|---|---|
| **原生系统通知**（仅安卓 App） | ★★★ 必响 | 网页算好未来 7 天的提醒点 → `AlarmManager` 精确闹钟 → 系统通知。锁屏、清理后台、App 被杀都能响；重启后自动重排 |
| 网页版应用内通知（浏览器） | ★★ 仅页面存活期间 | 定时器在**页面**（Service Worker 约 30s 空闲会被终止），到点调 `registration.showNotification()`；WebView 里没有这套 API，所以 App 内改走上面那条原生通道 |
| 回前台补发 | ★ 兜底 | 每次切回应用重算当天剩余课程，补发 5 分钟内错过的提醒 |

App 里怎么开：「提醒 → 开启系统通知」→ 允许通知 → 点「发一条测试通知」当场验证。
各厂商（小米 / OPPO·一加 / vivo·iQOO / 华为·荣耀 / 三星）的**自启动、后台活动、电池优化具体路径**见
[`docs/BACKGROUND-KEEPALIVE.md`](docs/BACKGROUND-KEEPALIVE.md)，App 内同内容在「提醒 → 后台保活设置」（自动高亮你的机型）。
ColorOS 额外两步更稳：**设置 → 电池 → 应用耗电管理 → 北邮课程表 → 允许后台活动**；**应用管理 → 北邮课程表 → 自启动**。

日历(.ics) 导出在 1.8.0 移除：早期版本靠它保证「必响」，现在原生闹钟已经能做到，两套并存只会让人搞不清该看哪个。

## 5. 节假日与调休

- 内置数据来源：**国务院办公厅《2026 年部分节假日安排的通知》（2025-11-04）**，逐日核对星期：元旦 1/1–1/3（1/4 上班）、春节 2/15–2/23（2/14、2/28 上班）、清明 4/4–4/6、劳动节 5/1–5/5（5/9 上班）、端午 6/19–6/21、中秋 9/25–9/27、国庆 10/1–10/7（**9/20、10/10 上班**）。
- **2027 年元旦**（1/1–1/3）为预留：国务院尚未发布安排，界面标注「待确认」，可在设置页修改。
- **补班日是「三态」的**（`followDayOfWeek`）：`1..7`（已确认按周X上课）/ `'none'`（已确认这天没课）/ `null`（**未确认**）。
  - 官方通知只规定「哪几天放假、哪几天上班」，**不指明补哪一天的课**，所以内置只有 `2026-01-04 → 按周五`（`inferred:true`，元旦仅借用 01-02 一个工作日 → 1:1 唯一解；UI 标「推定，请核对」），其余 5 天（02-14 / 02-28 / 05-09 / **09-20** / **10-10**）一律 `null`。
  - **`null` 绝不等于「没课」**：课表页会出**待确认卡**（周一…周日 / 不上课，8 选 1），该日状态为 `makeup_unconfirmed`、`complete=false`——**不排课、不生成提醒**，且页面任何位置都不会显示「今日无课」。
  - 确认入口：① 课表页卡片点选；② 设置 → 节假日与调休 → 6 行下拉（含「全部未确认日都不上课」批量）。逐日写入，**没有全局静默开关**。
  - 状态枚举（7 值，冻结）：`normal` / `holiday_silent` / `makeup_unconfirmed` / `makeup_skipped` / `makeup_follow` / `out_of_semester` / `unconfigured`。
- 法定放假日：课表页显示「XX假期 · 今日无课」，**不生成任何提醒、不导出该日事件**；可在设置页关闭「节假日跳过提醒」。
- **周视图里假期日不排课**（这是设计，不是丢数据）：那一列会打「假」角标 + 斜纹底色，顶部横幅写明「本周有 N 天法定假期，按设置不排课、不发提醒」；调休上班日未确认时列上标「待确认」，横幅带「去确认补哪天的课」按钮。
- 支持自定义日期（校庆、运动会）：设置 → 节假日 → 添加自定义日期（放假 / 补班）。

```bash
node .probe-capture.mjs             # 开发探针：真跑抓取脚本，验证能从课表表头读出「第1周 + 日期」
node .probe-holiday.mjs             # 开发探针：周视图的假期/待确认列必须自带角标与横幅
node scripts/build-android.mjs      # 构建 APK
```

> `.gate-shape.mjs` 钉死的是"形状契约"：`resolveDay` 必须返回对象（9 字段）、`status` ∈ 冻结 7 值、
> `NOTICE` 7 键且全为函数、四个样本日（10-10 / 09-20 / 10-01 / 01-04）语义正确、
> `getReminders` 返回计划对象。**它必须能对旧契约吐 `FAIL`（已实测：删掉 `effectiveDayOfWeek`
> 字段 → exit=1 并逐条列出缺失字段），否则等于没有门禁。**

纯逻辑层（`model / holidays / semesters / calendar / parsers/*`）**零 DOM 引用**，可直接被 Node 导入。UI 层不做任何日期/周次/节假日计算，只消费 `calendar.js` 的结论。

本次交付实测：**227 个用例全部通过**，0 失败；三道门禁 G16/G14/G18 均 exit=0。

关键契约（`resolveDay` 返回对象而非数组）由单测钉死：
`resolveDay(state,'2026-10-10').status === 'makeup_unconfirmed'`、`complete === false`、`effectiveDayOfWeek === null`；
而 `'2026-10-01'` 为 `holiday_silent`、`complete === true`（**才允许**说"今日无课"）。

## 8. 数据只在本机（没有账号，没有服务器）

课表存在本机 `localStorage['bupt_schedule_v1']`，**没有登录、没有云端、没有任何上报**。

| 想做的事 | 怎么做 |
|---|---|
| 换手机 / 重装 | 「设置 → 导出备份（JSON）」，到新机「设置 → 导入备份」（可合并或全量覆盖） |
| 清缓存前保命 | 同上，先导出一份备份 |
| 多设备同步 | 目前不做；两台机各导一份即可（数据不会互相同步，也不会冲突） |

技术约束（G4′ 门禁钉死）：

- 壳文件与 `src/**` **零外链**，唯一例外是「导入 → 跳转登录」里那条 `<a href>`（点了才打开教务系统，页面加载时零请求，且必须 `target=_blank + rel=noopener`）。
- 不接第三方分析、不发心跳；离线可完整使用（安卓壳里资源全部打包在 APK 内）。
- 隐私模式或存储写满时，顶部会常驻横幅提示「数据无法写入本机」。

## 9. 已知限制（诚实标注）

1. **网页版（浏览器）通知仍不保证送达**：系统清理后台后页面定时器停止。安卓 App 已改用原生系统闹钟（1.5.0+），不受此影响。
2. **必须先联网加载一次**才能装 SW；离线首访会提示需要联网。
3. **没有多设备同步**：数据只在本机，换机请用「导出备份 / 导入备份」。没有账号，也就没有"别人看你的课表"这回事。
4. **不做日历导出**：1.8.0 起移除了 .ics 导出，提醒统一走系统通知；想放进日历请自行把课表时间建日程。
5. **只做教务系统网页导入**：企业微信那套入口已移除（1.49.0）；若你手上只有企微里的课表文字，仍可用「粘贴文本」通道导入。
6. **节次作息以教务系统为准**：导入教务课表时会自动采用页面左列的作息表（北邮本科实际排到 **14 节**，晚课 19:20-20:55），所以第 12 节以后的课也能排进周视图；不同校区若有差异，可在「设置 → 节次表」改。
7. **调休上班日「补哪天的课」无公开数据可依**：内置只推定 `2026-01-04`，其余 6 个保持「未确认」，需要你按教务处通知在 App 内点选一次；未确认日不会猜测排课。
8. **不做账号直连教务**：登录一律发生在学校自己的页面里（App 内置 WebView），本 App 不接触密码。
9. **单学期**：不做多学期并存；跨学期请在设置页改学期起始日并重新导入。
10. **安卓 App 抓取需要校园网 / 学校 VPN**：`jwgl.bupt.edu.cn` 只在内网 DNS 解析（公网无记录），这是网络边界，不是 App 的限制。
11. **安卓 App 未上架应用商店**：APK 需自己安装（允许「安装未知应用」），首次安装时 ColorOS 可能提示风险，属正常。
12. **App 内抓取依赖页面结构**：抓的是课表页 HTML，学校改版后若抓不到，请用左侧菜单手动进入「课表查询」再点「抓取课表」，或退回「粘贴文本」通道。
13. **学期起始周可能需你确认一次**：若抓取时课表页停在「周次 = 全部」（表头不带日期），App 读不到当前周，会在预览页让你选「今天是第几周」；选过之后不再问。
14. **内置校历只覆盖已发布的学期**：目前是 2026-2027 第一学期（第 1 周周一 `2026-08-31`，来源：学校 2026-2027 学年校历）。新学期发布后需要往 `src/semesters.js` 补一行；在此之前 App 会走「按当前周反推」或提示手填。

15. **自动更新需要先保存一次账号密码**：学校登录页若改版或增加验证码，自动登录会失败并提示手动抓取——本地数据不受影响，也不会重复重试。
